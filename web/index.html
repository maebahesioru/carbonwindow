Median reduction, side by side
The honest part. Rows labelled forecast decide using the day-ahead forecast the API archived for that half hour — what a real deployment would have known. The forecast is good but not perfect (mean absolute error 12.6 gCO2/kWh, 95th percentile 39, worst 165), so a small share of arrivals end up worse than running immediately — up to -326% worse in the tail. Scheduling on a forecast lowers the median; it does not guarantee a saving on any single job.
Data quality, stated rather than cleaned. The snapshot contains 1 half-hour reading of exactly 0 gCO2/kWh (2026-08-06T11:00Z), while the lowest other reading in the whole window is 27 — so the 0 is almost certainly a missing value published as zero. It is left in every headline number above. Dropping it (turning it back into a gap, no interpolation) moves the reference-condition median from 25.93% to 25.72% under perfect foresight and leaves the forecast-driven median at 18.91%. The window medians barely move — it is one half hour out of thousands — but a single day only has 48 of them, so the same reading decides which day looks best: 2026-08-06 scores 56.8% in the day ranking below and 25.2% once the 0 is treated as a gap, at which point the best day becomes 2026-10-16 (48.2%). One bad row is worth 30 points on a day and a different winner — so the day ranking is labelled as perfect foresight, not presented as a plan.

Limits — read these before quoting a number
  • Indicator is average intensity, not marginal. Shifting load does not necessarily avoid the average mix of that half hour; a marginal-emissions model would give different numbers.
  • Great Britain only. The API covers the GB grid. Nothing here generalises to another country without replaying its own data.
  • Half-hour granularity. Sub-30-minute flexibility is invisible to this model.
  • Perfect stopping. A plan is assumed to complete inside its window with no preemption, retries, or cold-start cost.
  • Energy is assumed, not metered. The gCO2 columns scale linearly with the stated power; they are not a measurement of any real workload.
  • Historical replay. The forecast rows use the archived forecast, so they model what a deployment would have known — they are not a live trial.
